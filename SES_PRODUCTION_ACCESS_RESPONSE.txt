**EMAIL USE CASE**

We use Amazon SES exclusively for transactional emails that are essential to our platform's operation. All emails are triggered by user actions and are not marketing or promotional content.

**Types of Transactional Emails We Send:**

1. **Email Verification** (sent during user registration)
   - Purpose: Verify user email addresses during account creation
   - Frequency: Once per new user registration
   - Content: Contains a verification code/link that expires in 10 minutes
   - Example subject: "Verify Your Email - Ntsamaela"

2. **Password Reset** (sent when users request password reset)
   - Purpose: Allow users to securely reset forgotten passwords
   - Frequency: Only when explicitly requested by users
   - Content: Contains a secure reset link that expires in 1 hour
   - Example subject: "Reset Your Password - Ntsamaela"

3. **Delivery Notifications** (sent during package delivery process)
   - Purpose: Notify users about package status updates
   - Frequency: Triggered by delivery events (package created, bid accepted, pickup confirmed, delivery completed)
   - Content: Status updates about user's packages or deliveries
   - Example subjects: "Your Package Has Been Picked Up", "Delivery Completed Successfully"

4. **Bid Notifications** (sent to drivers and customers)
   - Purpose: Notify users about new bids on packages or bid acceptance
   - Frequency: Triggered when bids are placed or accepted
   - Content: Information about bids on user's packages or trips

5. **Account Security Alerts** (sent for security events)
   - Purpose: Notify users of important account security events
   - Frequency: Rare, only for critical security events
   - Content: Alerts about password changes, login from new devices, etc.

**RECIPIENT LIST MANAGEMENT**

**Opt-in Process:**
- All recipients explicitly provide their email addresses during account registration
- Users must verify their email addresses before they can use the platform
- No third-party or purchased email lists are used
- All emails are sent only to registered, verified users

**List Maintenance:**
- We maintain our recipient list in a PostgreSQL database
- Email addresses are stored only for registered users
- Users can update their email addresses in their account settings
- Inactive accounts (no activity for 12+ months) are automatically flagged

**Data Quality:**
- Email addresses are validated during registration using standard email format validation
- We verify email addresses through our verification process before sending transactional emails
- Invalid email addresses are rejected at registration time

---

**BOUNCE MANAGEMENT**

**Automated Bounce Handling:**
- We have implemented AWS SES bounce handling via SNS notifications
- When a bounce occurs, we:
  1. Immediately mark the email address as invalid in our database
  2. Log the bounce event for monitoring
  3. Prevent future emails to that address
  4. Notify the user (if possible via in-app notification) that their email needs to be updated

**Bounce Categories:**
- **Hard bounces (permanent failures):** Email address is immediately marked as invalid and removed from future sends
- **Soft bounces (temporary failures):** We retry up to 3 times over 24 hours, then mark as invalid if still failing

**Monitoring:**
- We monitor bounce rates daily through AWS SES console
- Our target is to maintain bounce rate below 2%
- We have automated alerts if bounce rate exceeds 3%

---

**COMPLAINT MANAGEMENT**

**Complaint Handling:**
- We have implemented AWS SES complaint handling via SNS notifications
- When a complaint is received:
  1. Immediately unsubscribe the email address from all future emails
  2. Mark the user's email preference as "do not email" in our database
  3. Log the complaint for review
  4. Investigate the cause (though rare, as we only send transactional emails)

**Prevention:**
- All emails include clear identification of Ntsamaela as the sender
- All emails are transactional and directly related to user actions
- We do not send unsolicited emails
- Users can update email preferences in their account settings

**Monitoring:**
- We monitor complaint rates daily
- Our target is to maintain complaint rate below 0.1%
- We have automated alerts if complaint rate exceeds 0.2%

---

**UNSUBSCRIBE REQUESTS**

**Transactional Email Policy:**
- Our emails are transactional (verification, password reset, delivery notifications)
- These emails are essential for platform operation and cannot be unsubscribed from
- However, users can:
  1. Update their email address in account settings
  2. Contact support to disable non-critical notifications
  3. Delete their account if they no longer wish to receive any emails

**Email Preferences:**
- Users can control delivery notification preferences in their account settings
- Critical emails (verification, password reset) cannot be disabled for security reasons
- We respect all unsubscribe requests for any non-essential notifications
